# 맥가이7 연동 — 알아낸 것 전부

**연동은 구현 끝났다.** 이 문서는 이제 "어떻게 하는지"가 아니라 **"어떻게
돌아가는지"** 를 적어둔 곳이다. 맥가이7이 화면을 바꿔서 멈추면 여기부터 본다.

| | 상태 |
|---|---|
| DB 테이블 (`lecture_attendance`, `lecture_overrides`, `macgai_sync_log`) | ✅ |
| 판정 로직 (`src/lib/lectureRules.ts`) | ✅ |

## 시크릿

`MACGAI7_ID`, `MACGAI7_PASSWORD` 를 **세 곳 모두**에 넣어야 돈다.

- Vercel production env
- 데스크톱의 `.env.local` (로컬에서 시험할 때만)

## 맥가이7이 도는 방식 (조사로 확인한 것)

API는 없다. 화면이 쓰는 요청을 그대로 흉내낸다. 아래는 전부 **실제 응답을
눈으로 보고** 적은 것이다.

### ① 로그인 — 폼 전송이 아니라 AJAX

로그인 버튼은 `<button onclick="fn_CheckForm()">` 이고 `__doPostBack` 대상이
아니다. 폼을 POST해봐야 로그인 화면만 돌아오고 쿠키도 안 생긴다.

```
POST /job/member_login_S01.aspx
     IN_M_ID, IN_M_PASSWORD, IN_M_BRANCH=""      (일반 폼 인코딩)
→ [{ M_IDX, M_ID, M_NAME, M_BRANCH, LOGIN_LEVEL, TOKEN, … }]
```

- 배열이 비면 → 아이디·비밀번호 틀림
- `LOGIN_LEVEL === "N"` → 로그인 권한 없는 계정

> **함정:** 맥가이7은 아이디·비밀번호에서 `- ' " / \ ;` 를 **지우고** 보낸다
> (화면의 `sanitizeInput`). 흉내내지 않으면 그런 문자가 든 비밀번호는 영영
> 로그인이 안 되는데 원인을 찾기 매우 어렵다. `sanitizeMacgaiInput`이 그것이다.

### ② 세션 열기 — 열쇠는 TOKEN

```
GET /c_index.aspx?m_idx=<M_IDX>&token=<TOKEN>
→ ASP.NET_SessionId 외 쿠키 20개 (CK_M_IDX, CK_M_BRANCH, …)
```

로그인 화면의 `Hd_*` 숨은 칸 17개는 채워지기만 하고 전송되지 않는다. 헷갈리기 쉽다.

### ③ 조회에 필요한 두 값

`/teacher/schedule/attend.aspx` 를 열어 스크립트에서 읽는다.

- `M_BRANCH` — 지점 번호 (예: `375`), 스크립트에 `var M_BRANCH = "375"` 로 박혀 있다
- 강사 번호 — `<select name="sel_staff">` 의 값 (예: `366794`)

### ④ 그날 학급 목록

```
POST /job/class_reset_S03.aspx
     in_c_branch, in_c_yyyymmdd, in_c_grade,
     in_c_category, in_c_bigcategory, in_c_teacher
→ 줄마다 { C_IDX, C_NAME, C_STU_CNT, T_TEMP, CHK }
```

> **함정:** 빈 값은 괜찮지만 **칸 자체가 빠지면** 서버가
> `"Fatal error encountered during command execution."` 를 뱉는다. 여섯 개를
> 항상 다 보낸다.

### ⑤ 학생별 등원 시각

```
POST /job/attend_S01.aspx
     in_m_branch, in_yyyymmdd, in_bigcategory, in_category,
     in_class,   ← C_IDX 들을 "||" 로 이은 것
     in_inout, in_m_grade, in_teacher, in_search,
     in_temp,    ← T_TEMP 들을 "||" 로 이은 것
     in_su_time
```

`in_class`가 비면 `STATUS: OK` 지만 **줄이 하나도 안 온다.** 그래서 ④가 먼저다.

### ⑥ 등하원 로그 — 학급에 안 묶인 날것

```
POST /job/attend_report_S07.aspx
     in_branch, in_s_date, in_e_date,
     in_aopt,   ← T_CNT / M_CNT / MI_CNT / N_CNT
     in_bigcategory, in_category, in_grade, in_school
```

출결현황 화면(`/teacher/schedule/attend_report.aspx`)의 "무수업생" 표에서
숫자를 누르면 열리는 명단이다. 인자는 화면의 `tb_no_study_click`을 그대로
옮겼다. 함정이 둘이다.

- **`in_aopt`는 칸 이름을 그대로 넘긴다.** `T`/`M` 같은 축약을 넣으면 오류
  없이 **0줄**이 온다. 이것 때문에 인자를 28가지 돌려보고도 못 찾았었다.
- **기간이 아니라 하루다.** 시작일과 종료일에 같은 날짜를 넣는다.

⑤와 달리 **학번이 `STU_NO`라는 제 칸으로** 온다. 이쪽이 중요한 이유는 학급에
묶이지 않아서다 — 토요일 반 학생이 일요일에 와서 찍어도, 수업 없이 클리닉만
하러 온 학생도 그대로 남는다. ⑤로는 둘 다 안 보인다.

### ⑤와 ⑥을 합친다

둘 다 읽어 `mergeCheckIns`로 합치고, 같은 학번은 **제일 이른 등원 시각**을
남긴다. 서로의 구멍을 메우는 관계라 어느 한쪽이 비어도 출결이 그만큼 나빠지지
않는다.

| | ⑤ 학급별 조회 | ⑥ 등하원 로그 |
|---|---|---|
| 클리닉만 온 학생 | 안 보임 | 보임 |
| 요일 옮겨 온 학생 | 안 보임 | 보임 |
| 결석/지각 사유 | 있음(SCHEINFO) | 없음 |

⑥이 실패해도 ⑤는 그대로 진행한다. 대신 크론 응답에 `logCount`(로그에서 읽은
줄 수)와 `logError`를 실어 보낸다 — **`logCount`가 계속 0이면 클리닉 자동
출결이 조용히 안 도는 것**이니, 확인할 때 제일 먼저 볼 값이다.

### 보내는 방식 — argString 통째로

`/job/*.aspx` 는 항목별 폼 필드가 아니라 **`"a=1,b=2,c=3"` 문자열 하나**를
본문에 담아 받는다. 폼 필드로 보내거나 쿼리스트링으로 붙이면 오류가 난다.

### 응답 모양

```json
[ { "STATUS": "OK", "DESCRIPTION": "" },
  { "COL": "ROWNO:STRING(-1),M_GRADE_NAME:STRING(-1),…" },
  [ [ …줄1… ], [ …줄2… ] ] ]
```

`COL`이 칸 이름 순서를 준다. 줄은 배열로 올 때도 객체로 올 때도 있어 둘 다 받는다.

### 학번은 `M_GRADE_NAME` 안에 있다

가장 헷갈렸던 부분이다.

```
M_GRADE_NAME = "고1<br>/51801"      ← 학년과 학번이 한 칸에
M_IDX        = "366801"             ← 학번이 아니라 내부 회원번호(6자리)
```

화면의 `학년/학번` 칸이 두 줄로 보이는 게 이것이다. **`M_IDX`를 학번으로
쓰면 안 된다** — 강사 번호(366794)와 같은 체계다.

### 결석은 `IN_TIME`이 빈 값

등원한 학생만 시각이 있다. 빈 값을 등원으로 넘기면 **안 온 학생이 출석으로
찍힌다.** `toCheckIns`가 걸러낸다.

## 동기화가 도는 방식

**Vercel Cron이 한국 시간 09:00~23:55에 5분마다** 부른다(`vercel.json`).

한동안 GitHub Actions에 예약을 걸어뒀었다. "Vercel Hobby 요금제는 크론이 하루
한 번뿐"이라는 **잘못된 전제** 때문인데, 실제로는 Pro라 1분 단위까지 된다.
그 우회가 오히려 사고를 만들었다 — GitHub은 부하가 걸리면 예약을 조용히 버린다.

2026-08-08에 실제로 확인한 것:

| GitHub에 걸어둔 주기 | 하루에 실제로 돈 횟수 |
|---|---|
| `*/10`(10분마다) | **2번** |
| `0 * * * *`(시간당 1번) | **5~8번** |

실패가 아니라 **아예 안 뜬다** — Actions 탭에 기록조차 안 남아서 눈치채기
어렵다. 그날 4시 강의 출결이 통째로 비어 있었던 원인이 이것이다.

`.github/workflows/`에 남은 두 워크플로는 예약이 없다. **손으로 한 번
돌리고 싶을 때 쓰는 버튼**이다(Actions 탭 → [Run workflow]).

> "마지막 자동 동기화"가 한참 전으로 멈춰 있으면, 코드를 보기 전에
> **Vercel 대시보드의 Cron Jobs에서 마지막 실행 시각부터** 본다.

## 멈췄을 때 — 조사 도구

맥가이7이 화면을 바꾸면 연동이 **조용히** 멈춘다(그래서 `macgai_sync_log`와
3시간 감시 푸시가 있다). 그때 원인을 찾는 도구가 있다.

```powershell
# 학원 데스크톱(Windows PowerShell)에서
cd ~\Desktop
Invoke-WebRequest -UseBasicParsing "https://raw.githubusercontent.com/triplej1107/student-management-app/main/scripts/macgai7-probe.mjs?v=$(Get-Random)" -OutFile macgai7-probe.mjs
$env:MACGAI7_ID="아이디"
$env:MACGAI7_PASSWORD="비번"
node macgai7-probe.mjs /teacher/schedule/attend.aspx --attend=2026-08-08
```

옵션:

| | |
|---|---|
| `--attend=YYYY-MM-DD` | 그 날짜로 학급→출결까지 실제 조회 |
| `--log=YYYY-MM-DD` | 그 날짜 등하원명단(⑥)을 구분별로 불러본다 |
| `--fn=이름` | 그 함수를 통째로 |
| `--find=글자` | 그 글자가 든 함수를 통째로 (이름을 모를 때) |
| `--save` | 원본 HTML 저장 (**학생 정보가 들어 있으니 공유 금지**) |

> 출력은 값을 가려서 나온다 — `김민찬`→`●●●`, `51801`→`99999`,
> 아이디·비밀번호→`(가림)`. 그대로 복사해 전달해도 된다.
