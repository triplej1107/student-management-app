# 디자인 계보 — 두 갈래로 나뉜 이유와 현재 상태

최종 갱신: 2026-08-04.

슬라임 아트는 **서로 호환되지 않는 두 계보**로 갈라져 있다. 어느 쪽으로 갈지는
아직 결정되지 않았고, 이 문서는 둘을 섞으려다 헛수고하지 않기 위한 기록이다.

## A. v5 코드 렌더 (직접 제작)

`src/lib/slimeSprite.ts` — 몸통·얼굴·아이템을 전부 코드로 그린다.

| 항목 | 상태 |
|---|---|
| 몸통 | 5속성, 만두형 실루엣 + 속성별 꼭지 |
| 성장 단계 | 알 / 베이비 / 틴 / 각성 **4단계 전부** |
| 표정 | 9종 (눈·입 픽셀 교체) |
| **아이템** | **103종** (레전 10 · 에픽 15 · 레어 20 · 매직 25 · 노말 33) |
| 해상도 | 셀 7px = 몸통 가로 약 **28칸** (레전·에픽은 셀 3.5) |

**장점** — 전부 우리가 만든 거라 몸·아이템·표정의 밀도가 일치한다.
안 예뻐도 어색한 데가 없다. 새 아이템을 코드로 얼마든지 추가할 수 있고,
속성·단계·표정·아이템의 모든 조합이 자동으로 나온다.

**단점** — 원장이 원한 그림체와 거리가 있다.

**장점** — 원장이 원한 그림체.

## 왜 두 계보가 안 섞이는가

**해상도 밀도가 9배 차이난다.** A의 아이템은 가로 28칸 기준으로 그려졌고,
B의 몸통은 가로 250px의 디테일을 가진다. 나란히 놓으면 아이템만 뭉툭한
다른 세계 물건처럼 보인다. 아이템을 2배로 키워도 격차가 남는다.

**격자가 없다.** B의 색 이어짐 길이를 재보면 1px 61% · 2px 12% · 3px 7% …로
흩어져 있다. 일정한 셀 크기가 없다는 뜻이고, 손으로 그린 도트를 여기에 맞출
기준선 자체가 없다.

**추출 손실이 매번 남는다.** B는 "검은 배경 위에 그려진 그림"이라 윤곽선과
배경의 밝기가 겹친다(실측: 배경 1~2, 윤곽선 하위 10%가 0~3). 완벽한 분리가
원리적으로 불가능해서, 시트를 받을 때마다 임계값을 다시 맞춰야 한다.
지금까지 고친 것만: 눈·입 뚫림 → 윤곽선 소실 → 흰 반투명 테 → 갇힌 구멍 →
속성별 윤곽선 밝기 차이 → 그림자 잔재.

## 그래서 갈림길

### 길 A — v5 코드 렌더로 되돌린다
- 오늘 당장 **아이템 103종이 전부 살아난다**. 가챠가 바로 굴러간다.
- 알·베이비·각성도 이미 있다.
- 대신 그림체는 포기.

### 길 B — GPT 아트로 끝까지 간다
- 그림체를 얻는다.
- 대신 **아이템 103종도 전부 GPT로 다시 받아야 한다.** 코드 아이템은 폐기.
- 추가로 필요한 것: 알 1장, 베이비 5장, 각성 5장, 그리고 아이템 103장.
- 아이템은 몸통 좌표에 맞춰 붙여야 해서, 손·머리 위치를 고정한 규격이 필요하다.

**섞는 길은 없다.** 위 세 가지 이유로 A의 아이템을 B의 몸통에 올리면
어색함이 그대로 드러난다.
